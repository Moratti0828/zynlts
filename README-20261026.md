## 现场启动

在本目录 PowerShell 运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

打开 <http://127.0.0.1:8787>。本机已有 Ollama 和 `qwen2.5:7b-instruct`、`llama3.1:8b-instruct-q4_K_M`，平台会检查两者是否在线。若 Ollama 未运行，在另一终端启动 `ollama serve`。首次模型加载较慢，每次请求最多等待180秒，实验后台串行执行以避免同时推理负载；模型驻留与卸载由Ollama管理。

其他机器可运行：

```bash
python3 -m backend.server
```

Windows 启动脚本依次尝试项目 `.venv`、Codex 自带 Python、`py -3`/`python`。端口占用可用 `./start.ps1 -Port 8788`。不要把 LibreOffice 内置 Python 误当作项目的通用运行环境。

本工作区已建立 `.venv` 并安装精确预算依赖。新机器如需启用该功能，在项目目录执行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-tokenizer.txt
```

`requirements-tokenizer.txt` 固定 `tokenizers==0.22.2` 和 `Jinja2==3.1.6`。新机器还需冻结匹配的 tokenizer；以下命令仅下载 `tokenizer.json`、`tokenizer_config.json` 并生成哈希清单，不下载模型权重：

```powershell
.\.venv\Scripts\python.exe -X utf8 .\scripts\freeze_tokenizer.py --repo Qwen/Qwen2.5-7B-Instruct --revision a09a35458c702b33eeacc393d103063234e8bc28 --dest runtime/tokenizers/qwen25-7b-a09a354
```

本工作区该目录已存在，无需再次下载；脚本会拒绝覆盖已有冻结目录。当前仅自动匹配 Ollama 的 `qwen2.5:7b-instruct` 及完整 digest `845dbda0ea48ed749caafd9e6037047aa19acfcfd82e704d7ca97d631a0b697e`。其他模型须另行核对 tokenizer、模板及运行时计数，不能因为安装了依赖就视为已认证。

## 验证和恢复

```bash
python -m unittest discover -s tests -v
```

`GET /api/health` 检查服务。重启会把未完成任务标为 `interrupted`，已有结果保留；新版结果页可续跑未完成项，版本或快照校验失败时拒绝续跑。取消会在当前请求结束后生效。恢复或迁移需在停止应用后备份整个 `var` 目录，并保存冻结 tokenizer。正式测试需同时封存题库、评分器、prompt 版本与模型 digest。

默认仅监听127.0.0.1。非回环监听必须设置`READING_BENCH_TOKEN`；反向代理、HTTPS与防火墙配置见部署说明。OpenAI兼容接入可使用服务器环境变量名`api_key_env`，密钥不存入前端和实验导出；这类接口未提供可信权重digest时不能进入严格版本门槛。

## 当前能力和边界

新版按题型分别报告选择准确率、短答 EM/字词 token F1、数值及单位严格正确率、段落证据集合 EM/Precision/Recall/F1；信息边界分别报告正确拒答、无答案实质误答与可答题误拒。中文、英文分别汇总并保留题数、文章数和失败数量。J 为答案与完整证据同时正确；U 是 D1—D5 五维宏平均，D6 拒答能力单独报告；两者属于本项目补充指标。中文短答 F1 使用字符单元，并非 LongBench 官方中文分词评分。

新版已接入界面、真实模型调用、成对文章簇 bootstrap、原始输出导出与未完成项续跑。匹配的 Qwen 使用冻结原生模板生成完整 prompt，通过 Ollama 原样输入接口调用，并核对预计算与实际输入 token 数；固定上下文 8192 token，同时预留输出预算和 512 token 余量。超限明确拒绝，不静默截断。其他未核对模型只可在开发模式使用明确标记的保守估算，正式运行必须启用精确预算与时间门槛。旧 v1 保留原 6000 UTF-8 字节/8192 上下文限制。

尚缺完整120篇问题标注、真实独立审题与隐藏集冻结、非Qwen配置的tokenizer/模板认证、自由摘要语义判断及完整权重谱系审计。当前20篇开发材料、单seed及暂定来源簇不能支撑总体排名；无适用题应显示N/A。没有自动联网/检索工具，数据采集与测评分开。服务器实际部署历史见 `docs/server-model-execution.md`，最新状态以本轮报告为准。时间规则检查已知首发/法规公布日与网页日期的最早值；未知旧稿、预印本与转载仍需人工检查，不可宣称“绝对无污染”。

## 使用服务器演示

本项目服务器使用独立目录`/home/jmy/reading-bench`，应用端口8787、模型端口11435均绑定回环地址。Windows校园WLAN下运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\connect-server.ps1
```

打开 <http://127.0.0.1:8877>，这是SSH隧道转发的服务器页面。保持该终端运行，Ctrl+C关闭隧道。脚本每次读取当前WLAN地址，不修改全局路由或代理；首次连接需要已有`gpu-server` SSH配置与可用密钥。普通SSH直连在本机代理路径握手失败时，脚本按使用指南执行逐连接WLAN中继。`-Background`可隐藏运行，PID保存到`var/tunnel.pid`。应用/模型运行在自己的tmux会话内，SSH断开不会停止服务器任务。

服务器当前使用GPU0推理，8个配置的矩阵已完成；旧CPU冷启动超时记录仅作历史故障证据。应用与Ollama分别由自有tmux会话保持，数据库一致性备份在`runtime/deployments/20261020/bench-final.sqlite3`；服务器重启后需按部署说明恢复进程。模型权重、原始逐题导出与数据库均保留。
