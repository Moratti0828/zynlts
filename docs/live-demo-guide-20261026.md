# 现场演示使用指南（2026-10-26）

现场演示使用平台真实模型接口。启动命令只检查平台、模型列表和题库，不会预先替你作答、下载权重或生成假结果。

## 三步开始

1. 在项目目录打开PowerShell，运行 `powershell -ExecutionPolicy Bypass -File .\launch-demo.ps1`。默认连接已有服务器平台；校园WLAN与 `gpu-server` 的SSH密钥连接需可用。脚本复用健康服务，或在后台建立8877隧道。
2. 浏览器打开 <http://127.0.0.1:8877/#demo>。确认页面显示实际模型可用，选择中文或英文演示材料、单题或多题，以及本次真实模型。
3. 点击开始。页面展示真实后台运行进度、模型回答和逐题评分，完成后查看完整记录或导出。首次加载权重可能较慢，等待页面状态更新；不要反复点击开始。

默认推荐可用的Qwen2.5 7B和中文单题，可直接点击开始；三题预设包含短答、选择题及信息不足题。模型选择仅开放完整原文预算适用的组合，Yi原生4K不能据此假定所有预设都适用。页面的模型连接检查不加载权重、不发推理。

服务器权重位于 `/home/jmy/reading-bench/runtime/models`，推理由服务器执行，浏览器不承担模型计算。入口中的 `127.0.0.1:8877` 是当前电脑的SSH隧道入口。

## 本机演示

已下载本机模型时可运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\launch-demo.ps1 -Local
```

打开 <http://127.0.0.1:8787/#demo>。脚本复用健康的本机平台；否则在后台启动项目平台，并在能找到Ollama且11434空闲时启动已有的Ollama服务。它不下载新模型。本机平台使用自己的模型注册配置，不会把服务器模型存在误报为本机已有；最终以演示页的实际就绪诊断为准。其他兼容接口可在“模型管理”中连接。

本机与服务器是两套运行环境，模型配置与历史实验可以不同。浏览器页面里的模型服务地址由平台后端访问；服务器平台的 `127.0.0.1` 表示服务器，不是观看者电脑。

## 启动检查和排查

| 情况 | 操作 |
|---|---|
| 只想确认准备情况 | `./launch-demo.ps1 -CheckOnly`；本机加 `-Local`。不会启动服务或推理。 |
| 端口占用但不是健康平台 | 脚本会停止启动流程，不会结束他人进程。确认监听服务，或用 `-Port 8878`（服务器隧道）/`-Local -Port 8788`（本机平台）。 |
| 服务器无法连接 | 检查校园WLAN、SSH配置 `gpu-server` 和密钥登录，查看 `var/tunnel.stderr.log`；可明确改用已准备好的本机模式。不会自动切换到另一套题库/模型。 |
| 平台健康但没有演示接口 | 当前运行的是旧平台进程。更新并由维护者重启本项目平台后再执行检查；脚本不会擅自停止监听进程。 |
| 页面显示无可用模型 | 检查“模型管理”的服务地址、模型名及连接状态。Ollama需已经下载对应模型；启动脚本不把“已安装Ollama”当作“已有模型”。 |
| 访问令牌 | 网页右上角输入部署令牌。命令行检查可从 `READING_BENCH_TOKEN` 环境变量读取；不要把令牌写进脚本或共享日志。 |
| 本机平台未启动成功 | 查看 `var/demo-app.stderr.log`；本机模型服务日志为 `var/demo-ollama.stderr.log`。 |
| 首题长时间没有答案 | 首次模型加载和实际推理都需要时间，页面会保留真实状态。确认模型服务/GPU情况；取消会在当前调用结束后停止后续题目。 |
| 刷新或短暂断网 | 回到演示页恢复最近运行，或在实验历史中找到该run；已有回答保留，不需重新整批作答。 |

默认后台启动的进程不会随着启动终端关闭而退出。项目PID记录在 `var/tunnel.pid`、`var/demo-app.pid`、`var/demo-ollama.pid`；PID可能过期，停止前必须确认实际进程属于本项目，不要仅凭旧PID结束其他进程。启动脚本不执行进程终止。

## 结果解释

现场演示是从固定开发题库发起的一次真实测评，不是正式模型排行榜。AI整理的近期题稿仍需人工复核；公开参考题可能已被模型训练见过。失败响应、拒答与错误答案均保留，不能将“运行完成”当作“全部答对”，不能用一次短演示代表总体阅读能力。
