## 2. 分阶段推进与出口

### A. 先调整评分与平台闭环（工程最高优先级）

1. 将论文核查后的指标定义写入可读取设计，主表分别输出选择题Accuracy、短答EM/F1、数值正确率、证据EM/F1及信息边界指标；J/U归补充分析。
2. 版本化题库、评分器、prompt、统计和结果结构。保留v1历史，不用新契约回写旧分数。
3. 打通模型配置→选择开发题→真实调用→自动评分→逐题文章证据→中英汇总→JSON/CSV导出。
4. 前端明确显示草稿/开发/正式状态、题型分母、预定/完成/失败数量。候选浏览与正式实验入口按数据状态区分。
5. 用“答对但证据错误、少一个必要证据、错数值/单位/否定、全拒答、无答案误答、格式失败、缺失响应”检查评分行为，再用少量真实开发题完成端到端运行。

出口：平台可现场运行一个真实实验，原始响应、金标、证据和分项评分可追溯。构造评分输入只能标为诊断，不能当模型成绩。

### B. 同时筛选题库，先交付开发集

平台开发与文章清理可以并行；模型排名依赖平台闭环完成。

- 从402篇中筛选120篇独立源文章，中英各60；先完成20篇开发（各10），再完成100篇隐藏测试（各50）。
- 保持六领域、相对长度和来源配额，按正文核定主题和体裁。任何一家来源不超过全库20%，至少8个独立发布机构；不能把转载站或机构下属栏目自动当独立机构。缺适合的论证、叙事或运算材料时定向补采。
- 对拟入选文章逐篇追溯原稿、预印本和数据披露；逐题记录必要答案是否为旧背景、本文新细节或跨段组合。已知更早版本、未解决疑点和时间证据不足分别保留，待核材料不自动升级。
- 同稿、译文、节选、同论文/事件及高度相似模板归源簇，禁止跨开发/测试。已演示文章只能留开发或参考轨。
- 保存“最早观察到的公开证据”，不要求宣称穷尽全球所有版本；正式结论使用“采取时间隔离并审查已知更早来源”，保留未知风险。审查对象同时包括完整文本版本及题目需要的新信息，不能因正文含历史背景就一律淘汰。
- 先为20篇开发集编制160题，再按适用性矩阵完成正式800题。每篇目标6可答＋2合理缺信息题；维度配额在全库满足，不给缺少运算条件的文章硬编计算题。

出口：开发160题具备清晰题面、答案别名/单位/容差、必要证据链和维度；正式集具有独立簇与实际覆盖清单。120篇与960题仍须以实物清单核验。

### C. 分批部署模型并验证GPU

先用固定Qwen2.5-7B打通GPU运行，平台真实闭环通过后再加入其余五款：Qwen2.5 1.5B/3B/14B、Mistral7B-v0.3、InternLM2.5-7B。

- 模型下载位置为`/home/jmy/reading-bench/runtime/models/<模型>/<固定revision>/`；逐文件核对源权重SHA，转换与量化另存工具版本、文件SHA、tokenizer及模板。
- GPU0/1/3的空闲快照只是候选条件，执行前重查资源并验证CUDA与真实推理；GPU2已报异常，不通过重置驱动处理本项目。
- 同一通过检查的GPU串行运行，采用同种Q4_K_M政策、各自原生模板、共同8K预算及512输出上限。逐模型完整输入，不将同一字符/字节数当成同一token数。
- 每款12题接口检查，共72次；覆盖中英、数值、证据、拒答与日志。14B显存或转换不兼容时先解决实现问题，记录原因与实际配置，不悄然换模型。

出口：六款均能被平台真实调用，版本可核验、输入无截断、请求与错误可追溯。这72次只证明工程链路。

### D. 开发初评、人审与冻结

真实双人审题及仲裁记录须按题保存，AI核对不能替代其中一人。先让真实审题人员试审10—20题，记录耗时和分歧，估算剩余工作。等待人审时仍可完成平台、AI草稿与标明草稿的试跑，不自动填入审核身份。

开发集160题完成审定后，六款各运行一次，共960次。检查格式、预算、金标歧义、难度和耗时；冻结题型配额、双语规范化、别名、证据替代链、prompt、解码、量化、重试与统计规则。开发结果标明开发集，不能当最终模型优胜结论。

对正式100篇/800题完成审题与仲裁，冻结文章/题/gold/hash、源簇、模型身份和评分版本。金标仅留评分服务，模型请求只包含正文、问题、选项和必要作答契约。审题工作界面不得使受试模型获得测试金标。

出口：冻结清单通过数量、独立性、时间证据、适用性、双人审题及实际token预算检查。冻结前修正提示和题目；冻结后保留原版，所有变更形成新版本。

主配对：Qwen1.5→3、3→7、7→14，及Qwen7↔Mistral7、Qwen7↔InternLM7。报告各指标差值、源文章簇95%区间和实际覆盖，不把同文8题视为8个独立样本。时延、显存和token吞吐另列。可选Llama按相同完整四阶段额外1,040次，或仅作明确标注的部分参照。

最终交付：可执行平台、启动与部署指南、模型身份清单、题库与审题清单、评分协议、中文结果、英文结果、比较区间、资源统计及限制。截图和录屏可辅助展示，实时运行与原始响应仍是验收依据。

## 3. 结果出来后的调整触发规则

| 发现的问题 | 调整方式 | 保留的约束 |
|---|---|---|
| 请求漏项、模型未实际用GPU、输入截断、计分契约错误 | 先修运行或评分问题，形成新版本，受影响的比较组按共同条件重跑/统一重评 | 原始失败与旧版本保留；不只重跑低分题 |
| 某模型输出格式错误多 | 在开发阶段核查模板/提示与解析；冻结后作为执行或契约失败报告，必要时另设新协议实验 | 不把阅读答错当网络失败重试至正确；所有模型使用同一政策 |
| 答案别名或替代证据链有合理争议 | 盲化模型身份、统一仲裁，修订评分版本并重评全部模型 | 不为个别模型临时放宽规则 |
| 高精度与Q4的排序/差值发生明显变化 | 分轨报告并解释量化敏感性 | 不混合不同精度的最高分拼榜 |
| 模型差值区间跨0或覆盖不足 | 报告差异不确定；必要时新增独立文章组成预先定义的新一轮测试 | 不反复抽子集直到显著；重复同题不增加文章样本量 |
| 多个无文章题可正确作答，或发现旧稿 | 核对题面线索、旧知识和来源；开发阶段替换不合适题，正式后按事先规则分层并另建新版 | 不凭无文章答对直接宣称污染，不按模型输赢删题 |
| 某领域/体裁不足 | 定向补采并先登记新轮配额；报告当前结论适用范围 | 不用简单提取题改标签凑跨句、运算或论证覆盖 |
| 新增较晚模型或更长上下文轨 | 重新核对共同时间合格文章、完整输入和推理预算，另冻模型/题库版本 | 不直接沿用2024模型的时间结论，也不混入不同预算主榜 |
