# AI 阅读理解测评：指标、实验设计与污染控制

原始资料核查日期：2026-10-11（中国标准时间）；2026-10-13 补充原论文/官方实现核查见[文献综述](literature-review-20261013.md)。**当前比较指标与执行计划以[研究与实验总计划](research-and-experiment-plan-20261013.md)为准**；120篇双语采编与自定义联合指标细节见[v2 执行协议](benchmark-protocol-v2.md)，构念审查见[设计审查](benchmark-design-review.md)。本文件保留原始资料及 v1 演示评分契约，不能把旧 F1 结果当成 v2 联合理解成绩。外部论文的分数不能当成本项目实测结果。

## 1. 测量对象与边界

项目的主要问题是：**给定一篇模型训练完成后首次公开的文章，模型能否依据所给文本回答问题、找到证据，并在文中缺乏答案时拒答？** 每道题提供完整固定节选，关闭联网、搜索、检索工具、对话历史和示例答案。当前题库含中英文；评测的是给定文本条件下的理解表现，不是通用知识能力，也不直接代表人的“阅读能力”。

题目分别标记：事实定位、跨句推理、数值/时间推理、主旨/综合、无法回答。正式报告同时按题型、文章、领域和长度分组。基准总分相同可能对应完全不同的能力结构；先报告分组结果，再讨论总体差异。

当前正式设计为 **120 篇，中文 60、英文 60，分别报告；20 篇开发、100 篇隐藏测试**。每篇目标 6 道可答题和 2 道难无答案题，共 960 题；正式隐藏集 800 题。先收集不少于 150 篇候选正文，再按领域、长度、来源和独立文章簇筛选，题目需真正满足能力定义。下载、AI 编题、真实人工审题、冻结测试数量分别显示。旧 8 篇/32 题只验证执行链路。

## 2. 来自主流基准的可操作指标

| 能力/质量 | 指标与方向 | 适用题目 | 主来源与本项目使用方式 |
|---|---|---|---|
| 答案正确性 | 严格准确率 / Exact Match（EM），越高越好 | 选择题、事实、数值、短答案 | [SQuAD 官方站](https://rajpurkar.github.io/SQuAD-explorer/)及[官方评分脚本](https://github.com/rajpurkar/SQuAD-explorer/blob/master/evaluate-v2.0.py)使用 EM/F1；本项目采用冻结后的中文规范化和答案别名 |
| 答案部分匹配 | 中文字/英文词 F1，越高越好 | 有可接受短答案的题 | 项目自定义的混合分词部分匹配指标；不是官方 SQuAD 或 LongBench 分数 |
| 选择与推理 | 选择题准确率、按推理类型的 EM | 跨句、因果、主旨选择题 | [RACE 论文](https://aclanthology.org/D17-1082/)提供阅读考试题思路；注意 RACE 的文本是英语，不能误称中文基准 |
| 数字与关系推理 | 数值答案准确率、错误类型 | 求差、计数、顺序、比例、日期 | [DROP 论文](https://aclanthology.org/N19-1246/)强调段落内离散运算；不要用普通文本 F1 为错误数字给高分 |
| 依据文本作答 | 证据集合 Precision / Recall / F1、证据 EM | 需证据的可回答题 | [HotpotQA 论文](https://aclanthology.org/D18-1259/)与[官方脚本](https://github.com/hotpotqa/hotpot/blob/master/hotpot_evaluate_v1.py)分别评价答案和句级支持事实 |
| 识别信息缺失 | 无答案拒答率、无答案误答率、可回答题误拒率 | 文中无答案题及对应对照题 | [SQuAD2.0 论文](https://aclanthology.org/P18-2124/)要求识别文本不支持的答案；不能只测可回答题 |
| 长文本表现 | 各长度组 EM/F1；长度增加时的变化 | 完整文本且实际上下文容纳的题 | [LongBench 论文](https://aclanthology.org/2024.acl-long.172/)提供中英长上下文多任务设计；[官方中文 F1](https://github.com/THUDM/LongBench/blob/main/LongBench/metrics.py)用 jieba 分词，与本项目字级 F1 不同 |
| 确信程度是否可信 | Brier score，越低越好；ECE 作辅助 | 有合法置信度和二元正确标签的题 | [Brier 原论文](https://doi.org/10.1175/1520-0493%281950%29078%3C0001%3AVOFEIT%3E2.0.CO%3B2)、[Guo 等校准论文](https://proceedings.mlr.press/v70/guo17a.html)；自报置信度需要实证校验 |
| 执行质量 | 完成率、JSON 合法率、超时率、耗时 p50/p95 | 全部预定题目 | 工程可用性指标，不混入理解能力结论；不能把请求失败伪装成模型拒答 |

## 3. 明确公式与评分规则

令测试题数为 N，预测答案为 a_i，可接受答案集合为 G_i，规范化函数为 norm。

- `EM_i = max(g in G_i) 1[norm(a_i) == norm(g)]`；总体 EM 是各题 EM 的平均。
- 单项选择准确率：合法选项与金标完全一致计 1，否则计 0。四个选项不等于“模型必有 25% 准确率”；25% 是均匀随机独立猜测的期望基线。
- 中文字/英文词 F1：规范化后中文字符逐字切分，英文单词与数字按项目评分器规则切分，以 token 的多重集合计算。交集 token 计数为 c，预测和金标 token 数为 p、g；`Precision=c/p`，`Recall=c/g`，`F1=2PR/(P+R)`。使用多答案时取最大 F1。无重叠时为 0；预测和标准都为空时为 1，但“无法回答”必须由题型及合法拒答状态确定，不能仅因 API 没返回文本获得 1。
- `Evidence_P = |E_pred ∩ E_gold| / |E_pred|`；`Evidence_R = |E_pred ∩ E_gold| / |E_gold|`；`Evidence_F1 = 2PR/(P+R)`。证据集合应使用稳定的段落/句子 ID。本平台若使用段落 ID，就标明“段落级证据 F1”，不要声称为 HotpotQA 句级分数。可回答题未给证据计 0；无答案题的空证据不混入可回答题证据平均。
- `Evidence_EM = 1[E_pred == E_gold]`。若有多套完整合法证据链，人工预先列出集合，取最佳匹配；不能临场按模型输出改金标。
- 可另报严格联合成功率：答案 EM 为 1 且证据 EM 为 1 的比例。它有助于区分猜对答案与正确定位；提供的证据不证明模型内部真实推理路径。
- 正式协议可采用全题分母：`无答案拒答率 = 正确拒答的无答案题数 / 无答案题总数`；`无答案误答率 = 作出实质答案的无答案题数 / 无答案题总数`；`可回答题误拒率 = 错误拒答的可回答题数 / 可回答题总数`。请求失败另计失败，因此拒答率与误答率未必加起来为100%。**首版实现采用有效响应子集**：`unanswerable_recall` 的分母为成功的无答案题数，`false_abstention_rate` 的分母为成功的可回答题数，`abstention_accuracy` 的分母为全部成功题数。界面显示有效样本数；不能将这些首版字段直接称为全题分母指标。分母为0显示N/A，失败仍在EM/F1分母中。
- 正确性校准使用 `Brier = mean((p_i-y_i)^2)`，其中 y_i 由冻结评分规则决定（严格 EM/选择题正确为 1，其余为 0），p_i 是模型声称“此次作答正确”的概率。这里采用二元单项版本，范围 0—1；与原始多类别求和版本的数值范围不同。不能拿 F1 当 y_i，也不能把拒答概率当“答案正确概率”。
- 置信度缺失或为null时保留答案评分，Brier排除此样本；非数字或超出[0,1]属于输出契约错误，首版将整条响应记失败，EM/F1计0。两种情况都不以0、0.5或1填充。Brier只针对有效置信度的成功响应计算，并报告有效样本数；若仅在可回答题计算，必须明确该子集。
- ECE：预先固定 M 个置信区间（例如 5 个等宽区间），`ECE = Σ_b (|B_b|/n) × |accuracy(B_b)-mean_confidence(B_b)|`。报告 M 和每区间样本量；小题库不应用单个 ECE 作强结论。
- `端到端完成率 = 有可评分有效输出的题数 / 预定题数`。同时给出“所有预定题上失败计 0 的 EM”与“仅成功请求上的 EM”，避免删去失败后抬高结果。耗时从发起模型请求到取得完整响应，预热与冷启动分开。

首版实现边界：当前平台使用 NFKC Unicode 归一化、英文转小写、中文按字符/英文按单词/数字按评分器模式切分，保留数字的 ASCII 正负号、小数点和百分号，并删除数字中的千位分隔逗号；其他未保留的标点和空白不参与匹配。`evidence_f1` 是**有效原文引句与标准金标引句拼接后的 token 重合 F1**；`valid_quote_rate` 是给出的引句中可在当前文章逐字找到的比例。它们可辅助检查引用，但不是上面定义的句 ID 集合证据 F1，也不检查引用是否完整支持推理。句 ID 集合 F1、Evidence_EM 和联合成功率是下一阶段建议，只有真正实现后才能纳入报告。

中文 norm 必须冻结版本并与代码一致。**不能通过删除符号把 `-3` 和 `3`、`1.5` 和 `15`、`5%` 和 `5` 等不同数字合并。** 数值题优先采用保留符号与单位的严格数值规则/显式答案别名；别名须在看结果前人工审定。

F1 只是表面字符重合。它可能奖励遗漏否定词、交换人名、错数字的答案。综合题建议改成预先给定的选择题或原子事实评分表；自由摘要可按“要点覆盖、事实支持、矛盾/遗漏”人工评审。ROUGE、语义相似度或另一个 LLM 打分可作辅助，但不能自动替代正确性金标。

## 4. 近期文章 + 早期固定模型：合理，但不是绝对无污染证明

| 模型 | 已核查时间信息 | 可以证明与不能证明的内容 |
|---|---|---|
| 原始 Qwen2.5-7B-Instruct | [Qwen 官方发布公告](https://qwenlm.github.io/blog/qwen2.5/)日期为 2024-09-19；[官方模型卡](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct)说明预训练与后训练 | 已存在于该日的固定权重，其生成/训练必在该日前完成；本次查阅页面未给出精确训练数据截止日。不能据模型名推定一个未声明的 cutoff |
| 原始 Llama-3.1-8B-Instruct | [Meta 官方模型卡](https://huggingface.co/meta-llama/Llama-3.1-8B-Instruct)列出发布日 2024-07-23，预训练数据截止 2023-12 | 预训练 cutoff 不是指令微调截止日；需以原始完整 checkpoint 的公开时间约束所有训练阶段 |
| 本机 Ollama 标签 qwen2.5:7b-instruct / llama3.1:8b-instruct-q4_K_M | 本机可执行候选；由部署清单记录模型摘要、量化与模板 | 标签可以重新指向其他文件；digest 固定运行文件，但单靠 digest 仍不能证明它来自原始 checkpoint。必须保留量化来源及对应原模型 revision |

这是一个条件性推断：**如果**所用权重确实是当时的固定原始 checkpoint（或从其仅量化而来的副本），且文章当时没有旧稿/预印本/重复发表，**则**后来首次公开的文本不可能以该公开文本形式进入早期训练。发布时间不能排除文中事实本来就已知、文章复用了旧内容、未披露训练样本或后来微调。结果可写为“采取时间隔离以降低污染风险”，不写“已保证模型绝不知道答案”。

建议本项目统一首发下界为 **2025-01-01**，初始重点收集 2026 年新文章。这个日期是本项目保守筛选规则，比上述两模型原始发布日期晚；最终必须逐条核验最早公开时间。HTTP `Last-Modified`、检索抓取日、网页更新日、论文正式出版日都不能替代首次公开时间。arXiv 核对 v1 时间；网页核对原始首发、转载来源及修改记录。

每篇文章留存：来源 URL、标题、作者/机构、许可/允许用途、原始首发时间和证据、当前版本日期、下载时间、完整原文 SHA-256、实际出题截取片段 SHA-256、截取/翻译/人工处理说明。若只保存摘要或片段，题目只能依据实际给模型的文本；不要把未保存全文误标为全文。

## 5. 污染、泄漏与偏差控制

1. 固定模型：保留原 checkpoint revision 和权重文件哈希；Ollama 另外保存 `/api/tags`、`/api/show`、版本和 digest。量化、chat template、system prompt、上下文长度、采样参数都是实验变量。每次正式运行前验证清单未变化。
2. 固定题库：开发集可以看错例；最终集在 prompt 调试结束后封存。对正文、题目、答案和评分脚本计算版本哈希。金标答案与证据仅交给评分器，不能拼进模型输入；也不在受试模型会读取的检索库中。
3. 人工标注：每题至少由两人独立核对可答性、答案、证据和题型；分歧先仲裁。若另用 AI 生成候选题，要记录生成器并由人复核，不能让受试模型生成自己最终试题和答案。
4. 重复核验：按 URL、正文哈希排重，并人工检查旧文章翻新、转载、预印本、同一事实叙述。正式测试不直接照搬公开基准旧题；那些基准只用于方法参考或单独的历史对照。
5. 用文对照：同题另跑“无文章”条件；若去掉文本后仍能高分，说明该题可能依赖常识、外部知识或存在泄漏，需要分析。无上下文答对不是污染证明，也不应自动扣分。
6. 反事实文本对照：少量由人核对的受控版本修改主体、数字或条件，并同步修改金标，测试模型是否随所给文本改变答案。标成“合成对照文本”，不能冒充下载原文章；与真实文章结果分表。
7. 干扰与长度对照：保持问题、金标和证据不变，加入无关段落或移动证据位置。新增文本必须仍落在所有模型已设置的实际上下文中，不能静默截断。长文本可在下一阶段扩展，当前短篇题库不能宣称已验证长上下文能力。
8. 公平条件：用同一题集、同一系统指令、同一最大输出预算、同一运行顺序策略。每模型单独清空对话；运行顺序随机或交替；避免某模型从其他模型答案中学习。
9. 报告局限：仅几个来源、单一题型、单一小模型、低精度量化或很小 N 都限制结论。Qwen 与 Llama 不只差在家族，也差在语言覆盖、参数量、训练与量化，不把差异归因于一个因素。

## 6. 实验记录和统计

正式归档应包含：run ID、时间、模型/模型digest、量化、服务版本、题库hash、prompt hash、评分版本、temperature、seed（若支持）、top_p、实际 `num_ctx`/上下文设置、输出上限、机器配置、逐题原始请求和响应、标准化答案、证据、拒答/置信度、错误与耗时。首版run JSON保存已发送参数和逐题快照，服务版本与机器配置另保存在部署清单及执行记录；未显式指定top_p时使用服务默认，不补造参数。当前证据是原文引句，不是句ID。API密钥不写入导出。

正式对比报告每个模型总体及每题型的分母 N、EM、中文字/英文词 F1、引句重合 F1（标明版本）、无答案拒答率、Brier 有效 N、完成率、耗时及代表错例。首版校准与拒答统计仅针对有效响应；尚未执行的题不在实时分母中，因此最终模型比较应等预定题目全部完成。首版显示平均耗时和 p95，p50、ECE、句级证据指标与文章 bootstrap 属于后续计划。样本太小时注明“演示性结果”。不先规定“模型必须达到 80%”这类无依据阈值；工程验收使用平台是否正确执行/记录/导出，科学结论使用固定数据上的实际估计。

置信区间建议按**文章**为单位 bootstrap，而非把同一文章的题当独立样本；不同模型使用同一重采样索引，报告差值及 95% 区间。预先设定 2,000 次重采样并固定 seed。若当前平台尚未实现这些统计，应导出结果后补算并注明；不要把规划写成已有能力。

## 7. 演示与验收清单

- 标准金标输出：预期答案正确、证据正确；错误答案、错误证据、非法置信度分别得出预期指标。
- 无答案题：模型正确拒答；故意填入文章外事实时计误答。
- 数值边界：`-3/3`、`1.5/15`、`5%/5`、单位不同不能被自动当同答；空字符串不能冒充有效答案。
- 接口故障：断开 Ollama、错模型名、超时、非 JSON 响应，运行明确记录失败；界面不展示虚构模型回答。
- 时间边界：早于/等于模型公开日的文章、不明首发日期的文章、旧稿转载，不进入“时间隔离已核验”子集。
- 复现：重复同一冻结配置，保存原始结果，核对题库与模型 hash；温度 0 仍不能承诺跨硬件/服务版本位级确定性。
- 现场展示顺序：查看文章及来源 → 查看问题和模型设置 → 发起真实推理 → 显示答案/证据/逐题分数 → 展示失败案例 → 导出 JSON/CSV。使用模拟输出时必须明确标注为评分器测试，不算真实模型测评。
