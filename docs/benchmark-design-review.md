# 从演示平台到阅读理解测评：能力定义、评分与百篇题库设计

设计审查日期：2026-10-11（中国标准时间）。本文件是针对当前平台的独立设计建议，**不代表文中新增指标、正式题库、人工审题或统计分析已实现**。审查依据为 `backend/scoring.py`、`backend/server.py`、当前 `data/corpus.json` 与方法文档。当前 8 篇、32 题能验证真实推理链路，不能支持总体阅读理解能力排名。

## 1. 首先明确究竟在测什么

建议项目测量对象固定为：**在关闭联网、检索和对话历史时，模型依据实际提供的陌生文本，准确恢复信息及关系、整合证据、形成文本支持的结论，并识别文本不足以支持的答案。** 受试者是固定权重、固定量化、固定提示词与推理配置下的模型系统。

这一定义包含“答对”和“有文本依据”两个要求。答对一个常识问题、复述一个原文数字或生成流畅摘要，均不能单独证明充分理解。当前项目也不测人的阅读动机、阅读习惯、视觉识字或浏览网站技能；不能把模型分数换算为 PISA 人类能力等级。

OECD 的 PISA 阅读框架区分信息定位、理解、评价与反思，并讨论文本类型、单一/多个来源及任务难度。本项目借其构念划分做内容覆盖设计，重新定义适用于文本条件模型测评的可观察任务；**以下六维是项目操作化方案，非 OECD 官方六维量表**。[OECD PISA 2018 Reading Framework](https://www.oecd.org/en/publications/pisa-2018-assessment-and-analytical-framework_b25efab8-en/full-report/component-3.html)

## 2. 六个能力维度与能证明该能力的题

| 维度 | 所需操作 | 可执行题型与证据要求 | 不能拿来代替的任务 |
|---|---|---|---|
| D1 信息定位与准确释义 | 从干扰信息中找到主体、对象、时间、条件，并保留否定和范围 | 短答案或选项；1 个主要证据句，可有明确释义别名 | 摘到任意含问题关键词的句子 |
| D2 语义、指代与条件理解 | 保留否定、限定范围和例外，解析代词与条件规则，识别被反驳的前提 | 释义/规则应用/指代消解/情境判断；支持原文的 1—2 个主要句子 | 丢弃“不/仅/除非”后靠关键词选答案 |
| D3 跨句整合与推断 | 连接至少两个不同信息单元，恢复关系、先后、因果或比较结论 | 跨句/跨段短答案或选择；至少 2 个必要证据句，记录最短推断说明 | 直接照抄单句规则后回答是/否；把作者观点当事实 |
| D4 数值、时间与集合推理 | 根据文本内多个值进行求差、计数、排序、比例或日期关系运算 | 结构化数值/集合；记录操作数、单位和确定性计算规则 | “多少日内”直接取出文中 30；这属于 D1 |
| D5 主旨、结构与论证评价 | 识别目的、主旨、段落作用；区分数据和主张，判断证据与限制能支持什么 | 主旨/结构选择题、原子要点题，或“支持/反驳/不足以推出”；关键证据跨段或包含主张和论据/限制 | 只给一段摘录却声称测全文主旨；凭词面重合评摘要；凭机构名或外部常识判断现实真假 |
| D6 可回答性与知识边界 | 识别给定文本是否足以确定答案；不以常识填补未给出的信息 | 2 类难无答案题与可答对照：缺必要条件/属性；近似实体、时间或范围错配 | 每题统一拒答；非常离题、可由题面轻易识别的无答案题 |

每题记录一个主要维度，附多个次级标签（例如否定、指代、条件、跨段、单位）；避免把同一道题重复加入多个维度的主分母。D3 推断必须在金标记录连接步骤；D4 必须真的需要运算；D5 全局题必须保留足以形成全局理解的文本，论证题的判断依据和必要评价标准必须在文本/题面中明确，避免测到领域常识。D5 内分别报告主旨/结构与论证次级标签，防止仅做主旨题却宣称已测批判阅读。

无答案和错误前提须严格区分：若文章明确“厨房不得单独出租居住”，问“可以出租吗”可回答“不可以”，应归 D2 的否定/规则理解；若文章明确写“研究不能推出因果”，问“文本是否支持因果主张”可回答“不支持”，应归 D5 的论证评价。只有缺乏足够信息确定所问属性、实体或关系时，才是 D6 无答案。全国平台日访问量这类显然离题的问法可用于评分器验收，不能成为正式无答案题的主要来源。

多文档对照、图表和超长文本是另外的扩展轨道。若将两篇文章组成比较任务，其全部文章及衍生题必须进入同一数据划分和统计簇；第一版单文档结果不能宣称已覆盖这些能力。HotpotQA 用多文档问题和句级支持事实检验复杂推理，可借鉴其证据标注方法。[HotpotQA 原论文](https://aclanthology.org/D18-1259/)

## 3. 主指标：答案与证据联合成功，而非仅 F1

### 3.1 逐题规则

给实际呈现文本的每个句子一个稳定 ID（例如 `a123:p03:s02`）；分句规则、文本、ID 映射一起冻结。受试模型返回答案和支持句 ID。若首版先用稳定段落 ID，同样可做集合评分，但须标明“段落级”，按完整段落标注金标，不能称句级分数或把两个粒度直接混算。金标可以预先包含多套完整且最小的合法证据集合；**不能看见某模型输出后再挑选有利金标**。

令 `A_i∈{0,1}` 为答案正确，`P_i` 为预测支持句 ID 集合，`E_i={E_i1,…}` 为预先审定的合法证据集合族。

- 选择题：选项严格正确，`A_i=1`；冻结选项并平衡正确位置，不能按模型输出重新排列。
- 短答案：冻结实体/关系含义及明确别名；语义相同但未列出的表达交给盲审仲裁，并以统一更新版本重评全部模型，不能只给一个模型加分。
- 数值题：按冻结数值、符号、单位及容差规则判定；单位换算和容差仅在题目适用时允许。不得用 token F1 给错误数字部分正确分。
- 要点题：先给出原子事实、必要限定条件和矛盾规则；严格正确要求全部必要要点覆盖且无矛盾。开放表达若采用人工评审，评审者不看模型身份；LLM 评审仅作辅助，需另报人与评审模型一致性。

`S_i = max_k 1[P_i = E_ik]` 是严格证据集合成功；未知 ID、缺少任何必要支持句、附加无关支持句均失败。另报告句集合 Precision/Recall/F1 作为部分覆盖诊断。严格集合规则会惩罚合理但未列入金标的证据，因此正式前需要复核替代证据链并记录标注分歧。

**可回答题严格联合成功：`J_i = A_i × S_i`。** 同时展示“答案对/证据对”四象限：两者都对、答对证据不足、证据对答案错、两者都错。它可以识别猜对或引用错误，但不证明模型内部推理过程。

### 3.2 汇总与拒答

对 D1—D5，在包含该维题目的每篇文章内先求联合成功均值，再对这些文章均值求平均，得到 `U_d`；中英文分别算 `U_d`，总览可用两语言等权结果。主要阅读成绩为五维等权宏平均 `U=(U_1+…+U_5)/5`；必须一起报告每维分数、覆盖文章数、题数及置信区间。某文章未设该维题目不视为零分，也不能伪造该维样本。每维等权是本项目预先声明的覆盖策略，非自然界存在的“理解能力权重”。不得让一个来源额外生成大量简单题后自动主导总分。

**D6 与 U 并列报告，默认不与耗时、Brier 混成总分。** 设正式题中的无答案题为 `N_u`、可回答题为 `N_a`：

- 无答案正确拒答率 `R_u = 正确拒答无答案题数/N_u`。
- 无答案实质误答率 `H_u = 在无答案题给出实质答案数/N_u`。
- 可回答题误拒率 `F_a = 对可回答题拒答数/N_a`。
- 可回答题有效作答率 `C_a = 对可回答题给出合法实质答案数/N_a`，此处作答不等于答案正确。
- 可回答性平衡准确率 `B=(R_u+C_a)/2`。总拒答策略和总作答策略在没有执行错误时均只得到 0.5，避免题库无答案占比决定“聪明”的假象。

请求/格式错误单独为第三种输出状态，对上述成功项计 0，报告两类题的错误率；所以 `R_u+H_u` 与 `F_a+C_a` 在存在错误时不必为 1。无答案题的正确拒答定义与统一 JSON 契约一致，拒答必须无实质答案、无伪证据。另报可回答题答案准确率和联合成功率，避免“愿意回答”被误读为“正确理解”。若只计算有效输出子集，必须另标有效分母，不能与全题协议混用。

若现场需要一个单值，可另显示固定 75% 可答、25% 无答案构成下的“全题有依据成功率”：可答题用 J，无答案题用正确拒答。它仅是该固定分布的端到端成功指标；始终同时展示 U、B、误答/误拒率，不能脱离分布比较不同题库。

### 3.3 辅助指标与 F1 的局限

EM、字/词 F1 仍用于核对与错例诊断；句集合证据 F1 表示证据覆盖；Brier/ECE 表示置信度与严格正确标签的关系；完成率、格式合法率和耗时表示工程可用性。模型自报的“答案正确概率”应以 A 为校准标签；只有提示词明确定义为“答案及证据联合正确概率”才能以 J 为标签，不能悄悄更换。它们回答不同问题，不能用耗时快或置信度高抵消答错。报告所有预定题失败计 0 的成绩，并附成功响应子集成绩、覆盖率；已取消的运行只能称未完成。

当前 `scoring.py` 的 F1 是字符/单词多重集合重合：句子重排、交换主体、遗漏否定或错一个关键数字，可能仍有高重合。例如“甲不支持乙”与“甲支持乙”只差否定字符，含义却相反。其引句 F1 是引句拼接后的 token 重合，不检查引句是否完整支持结论，也不等于 HotpotQA 句级证据分。当前没有严格联合 J、句 ID 集合或按文章宏平均。不能把现有引句 F1 重命名后当成它们。

DROP 的设计要求对文本信息做离散操作，正好说明数字直接抽取与数值推理应区分。[DROP 原论文](https://aclanthology.org/N19-1246/) SQuAD 2.0 则要求既在有支持时作答，也在没有支持时拒答，其无答案题刻意接近可答题，不能用大量显然离题的问题替代。[SQuAD 2.0 原论文](https://aclanthology.org/P18-2124/)

## 4. 至少上百篇：建议 120 篇、960 题，100 篇进入隐藏测试

**最低正式设计是 120 篇独立文章，每篇 8 题：20 篇开发/校准，100 篇隐藏测试，合计 960 题。** 其中正式隐藏集 800 题：600 可答、200 无答案。现有 8 篇若审核通过可计入开发集，不能因为已经看过结果再称隐藏测试。

先收集 160—200 篇候选以补淘汰；候选下载数量、去重后文章数、可出题数、人工审定数、冻结测试数分开显示。120 篇同一发布源的近似模板公告，仍不足以支撑宽泛能力结论。

| 分层因素 | 初始配额/规则 |
|---|---|
| 语言 | 中文 60、英文 60；开发各 10、测试各 50。报告两种语言分别成绩，不能把差异完全归为模型理解水平 |
| 领域 | 科学技术、环境与能源、公共政策、社会与文化、健康与生命科学、经济与产业 6 类，各 20，每类中文 10、英文 10；健康文章仅测文本理解，不给诊疗结论；文本必须包含足够信息支撑相应任务，分类细则在测试前冻结 |
| 长度 | 每语言短/中/较长各 20；参考中文 300—600、600—1200、1200—2000 汉字；英文 200—400、400—800、800—1400 词。实际共同入选条件是所有模型的完整渲染输入与输出保留量均能容纳，记录各 tokenizer 实际长度 |
| 组合 | 6 领域×2 语言×10 篇=120；每个领域-语言格的 10 篇按长度 3/3/4 分配，轮换多出的一篇，使每语言各长度总数 20。开发 20 篇保持语言 10/10，各领域抽 3 或 4 篇；正式集各领域 16 或 17 篇，分层配额与划分清单先冻结 |
| 来源/体裁 | 优先有可保存许可的近期原始文本；至少 8 个独立发布机构，任何一家不超过 20%；解释/报道、说明/操作、论证、叙事等文本均需覆盖；避免领域与唯一来源完全重合 |
| 公开时间 | 最早公开时间晚于所有受试固定权重公开时间；统一 2025-01-01 后首发，优先 2026；有旧稿/预印本则以更早时间判定。日期证据不明的进入候选隔离区 |

这些长度用于第一版相对长度分析，不能称为 32k/128k 长上下文评测。当前 API 的 6000 UTF-8 字节门槛会拒绝部分中文中/较长文章；必须先实现各模型实际 tokenizer/模板预算校验，或诚实调整文章长度并缩窄结论。保存全文但实际仅给节选时，将其标记为“节选测评”；同篇拆出 10 个节选仍只是一篇源文章。

每篇 8 题固定构成为：6 道可回答题、D6 无答案 2 道。**维度配额在题库层实现，不要求每篇都有数字运算或论证评价。** 每篇可答题至少覆盖 3 个维度，同一维度最多 3 道；无合适数字的文章不出 D4，无适当主张/证据的文章不硬出 D5 的论证子类。100 篇测试的 600 道可答题，目标 D1—D5 各 120 道，每维中文/英文各 60，道题承载至少 40 篇不同源文章（尽量达到 50），并覆盖多个领域及长度。开发集的 120 道可答题目标各维 24 道、中英文各 12；测试 D6 为 200 题、开发 D6 为 40 题。先建文章-维度适用性矩阵，再分配配额，不把数字直接摘取改标签凑推理数量。

上述配额是一份采编目标；若候选正文的结构无法满足，补采适合文章或调整并预登记实际分布，不应生成语义不自然、答案歧义或需要外部常识的题来达标。最终报告实际维度×语言×领域×长度覆盖，明确尚未覆盖的单元。

无答案题一题缺关键条件，一题使用合理但错配的实体/时间/范围；在同主题上配可答近邻，题面风格、长度和答案类型接近。难度不是靠让文章更长或题面更绕：记录证据数量、跨度、干扰数量、限定条件数量及操作步数；在开发集人审/试测后确定易中难，不能根据目标模型输赢挑题。

跨题推理和 D5 问题宜采用冻结选择题/结构化短答，开放要点题小比例、预置人工评分表。题目要求回答格式应统一到尽可能轻的契约，证据只需 ID，从而减少当前复制整段证据导致的输出截断；需保留实际格式错误率，不能隐藏。

## 5. 标注、冻结与污染控制

1. 文章记录原始 URL、许可、最早公开时间及证据、下载时间、正文和实际呈现文本 SHA-256、领域/体裁/长度、源文章/来源簇 ID。按 URL、全文哈希、相似正文/旧稿检查去重；相同文章的转载、翻译、缩写、节选和同事件高度近似报道放同一簇。
2. AI 只生成候选题并核查来源；记录生成模型和生成时间。两位人类独立核对题面、可答性、标准答案、所有必要证据、维度和歧义，分歧仲裁后才能进入正式集。记录真实审题者与时间，不能自动替用户填审批。
3. 数据状态拆成 `candidate → ai_checked → human_reviewed → frozen`。当前 `reviewed=true` 配合“待独立人工复核”只能算来源核对状态，不等于人类正式审定。平台应显示四种数量。
4. 开发/测试以源文章簇划分；同原文的不同题、翻译与反事实版本不得跨界。开发集可调 prompt、别名、预算和评分；隐藏集在规则冻结后只做最终推理和盲审，不根据效果改规则或淘汰输题。
5. 固定模型 digest 及量化来源，冻结正文/题/金标/句 ID/评分器和提示词版本；金标只在评分服务，不放模型请求或检索库。测试模型不生成自己的最终题库。
6. 无文本对照只能筛出可能靠先验知识可答的题，不能证明训练污染；合成的数字/实体/条件反事实对照须单独标注、单独报告，检查模型是否跟随当前文本。不能把无文本答对自动认定为作弊或直接扣分。

时间隔离约束训练公开时间与文章首次公开时间，可以降低公开文本泄漏风险；它不能排除旧事实、相似文本、预印本、后续微调或来源不透明的量化模型。因此正式结论写“采取时间隔离”，不写“模型不可能知道答案”。

## 6. 统计单位、复现与能说出的结论

正式对比使用完全相同的隐藏文章与题，两模型成对评价。中英文各 50 篇分开报告，再给等权总览；对每模型先计算文章内的分数，再比较文章/能力宏均值。采用按语言/领域/长度分层、以源文章簇为单位的成对 bootstrap，2,000 次、固定 seed、同一抽样索引用于所有模型，给出 U、各维和模型差值的 95% 区间。若文章簇包含多个版本/文章，抽样时整体进入。每维仅含适用文章，报告其覆盖数；各维覆盖不同文章时，不把维度分数的高低直接解释为内在能力强弱，需结合任务难度和内容分布。

800 题不是 800 个独立样本。同一文章 8 题受共同文本、主题及难度影响；100 篇也不天然保证能分辨 2—5 个百分点的模型差异。应以开发集的文章成对差值方差估计正式样本需求；若区间跨 0，就报告在本题库下差异不确定。不能先选高分或显著维度再声称总体优胜，多维探索结果需标明。

固定温度 0、随机或交替运行模型，清空历史；每题完整原始响应及请求、错误、输入/输出 tokens、预算、耗时、硬件、模型版本、服务版本均保留。正式首轮每模型 800 次请求；若检测到非确定性，再对预先指定的分层子集至少 3 次重复，重复运行不是新增独立文章。所有失败计 0 的结果衡量端到端表现，另报告格式/服务错误和成功子集以解释工程影响。

最终允许的结论是“在这个固定双语、六领域、长度范围和任务分布的题库上，该模型的文本依据成功率和能力结构如何”。不允许外推到全部语言、全部领域、人类阅读等级、超长文档、联网检索、所有同家族模型或保证无污染。

### 人工核验工作量与诚实阶段

按 960 道候选题、每道每位审题者 6—10 分钟估算，两人独立审题需约 **192—320 人时**；120 篇日期/许可/重复检查约 20—40 人时，分歧仲裁和冻结抽检另预留 20—40 人时，合计约 **232—400 人时**。这些是排期假设，不是已完成审题记录；先让两位真实审题者完成 10—20 道试审，测量实际耗时和分歧率，再调整。结构化证据 ID、候选答案/计算步骤、来源旁读可以降低核验成本，但 AI 的“已核对”不能顶替第二人。

建议交付阶段分清：①平台与设计协议；②≥150 篇真实候选正文及来源清单；③120 篇分层入选正文与 960 道 AI 核对候选题；④完成真实独立审题、仲裁与冻结的 100 篇/800 题隐藏集；⑤正式测评与统计。前 3 阶段可以由工具推进，当前缺人审时仍可在平台展示和试跑候选，但必须显示候选状态与样本数，不能称最终正式测评。用户不需为候选采集反复审批，也不能被工具自动签成人工验收。

## 7. 当前平台必须补齐的实现，不应直接开始所谓正式排名

| 当前状态 | 正式测评缺口 |
|---|---|
| 8 篇/32 题，4 标签；多为短节选 | 120 源文章分层、6 维任务、真正运算/跨句/全局/论证题，20 开发+100 隐藏 |
| AI 核对来源并设 reviewed=true | 状态和独立人工复核记录，公开候选/已审/冻结数量 |
| 答案 EM/F1 与引句 token F1 | 稳定句 ID、合法最小证据链、数值/要点规则、严格联合分与四象限 |
| 以已记录题的均值聚合，按4标签分组 | 按文章/维度/语言/领域/长度宏平均，全题有效分母、预定/已执行/错误数量 |
| 拒答仅在成功响应子集算比例 | 全题拒答/误答/误拒/错误率与平衡准确率，子集分母明确 |
| 6000 UTF-8 字节固定输入限制 | 各模型真实模板/token预算，较长文本完整呈现且不截断 |
| 单次运行及少量错例 | 成对按文章簇置信区间、冻结运行清单、盲审与复现记录 |

实施顺序应为：冻结本协议和评分规则 → 平台支持维度/证据/状态/分母 → 分层采集候选并保存来源 → 先用开发集验证题目与评分器 → 独立复核与封存100篇测试 → 正式运行 → 按文章统计并展示结论。评分器验收必须覆盖答案正确但证据错误、仅少一个必要证据、错数字/单位/否定、无答案误答、可答误拒、格式/超时等已知错误；不能用受试模型高分作为评分器正确的证据。
