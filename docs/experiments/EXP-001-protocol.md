# EXP-001：短答 F1 别名评分的重复计数成本

状态：执行前约定，2026-11-17。工程微基准，不是模型推理实验。

- 问题：同一预测与多个参考别名比较时，将预测 Counter 移到别名循环外是否减少评分时间？
- 原方案：`scripts/baselines/short_f1_v1.py`，本轮修改前的算法原样保留；候选：`backend/benchmark_v2.py:short_token_f1`。两者共用未改动的 `answer_tokens`。
- 固定：UTF-8 输入、别名顺序、分词/规范化/空输入/多重集 F1 语义、同一 Python 进程与机器。合成中英输入覆盖重复词、否定、Unicode、纯标点、空别名和 1/4/16 别名；不伪装真实模型回答。
- 质量门槛：已知正例与负例通过，所有逐项浮点结果完全相等，否则 FAIL 并保留差异，不采用候选。
- 运行：固定 3 轮，每轮每方案处理相同输入 20 遍；交替先后顺序。计时包含分词、Counter、逐项评分和结果列表构造，不含导入、输入读取、文件输出。每轮保存全量输出、错误和非零实际耗时。
- 判断：完整质量检查通过且候选耗时中位数小于原方案，才有限采用；否则保留原方案或继续检查。不承诺整个平台吞吐、模型推理速度或跨机器倍数。
- 停止：异常、输出不一致或测试失败时不扩大实验。输出目录必须全新，拒绝覆盖原证据。
- 成本：记录每轮秒数；模型调用为 0（此脚本无网络）；人工分钟、AI开发费用、内存及后续维护成本未记录，填 null，不能当零。
- 入口：`python scripts/compare_short_f1.py --output evidence/EXP-001-local`。结果 `result.json`，内含输入、脚本/协议 hash、逐次输出、成本与决定。伙伴使用自己的新目录独立运行。

协议文件 SHA 会随结果保存。历史模型结果不因本次实现优化重写。单人组金明源负责核查结论，伙伴独立执行状态另见 review/peer-plan.md。
