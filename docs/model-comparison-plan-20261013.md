# 双语阅读能力模型对比计划

资料核查日期：2026-10-13（北京时间）。本次完成官方模型卡、发布记录、Hub 参数统计与历史原始权重摘要核查，未下载或部署新模型。当前模型服务与 GPU 能否执行完整实验，必须重新实测；以前的 CPU 演示不代表本计划已经执行。

## 1. 要回答的研究问题

1. 在相近参数档位下，不同研发机构的指令模型对同一份陌生文本的理解表现如何，差异出现在哪个语言和能力维度？
2. 在 Qwen2.5 同一代通用 Instruct 系列内，模型从约 1.5B 增长到约 14B 时，答案、证据、信息边界识别和成本如何变化？
3. 成绩是否依赖记忆已有知识、量化或输出格式，而非所提供文本？通过单独的诊断实验检验，不把诊断分数混入正式主成绩。

跨机构模型在语料、训练量、分词器、结构、对齐方式和语言覆盖上都不同，比较结果是这些固定 checkpoint 的总体表现差异，不能归因为“公司”这个单一变量。同一系列不同规模也不保证训练过程完全相同，属于规模趋势比较，不是参数量的严格随机因果实验。

六款主模型的全部 safetensors 路径、大小与 LFS SHA256 在上述两版之间均一致。后续 README、模板、代码更新日期不能自动解释为权重重新训练。相反，也不能只看“2024 系列”名称就接受任何后续微调权重。

公开的不可变原权重存在时间，可作为该份训练成果已经产生的上界证据；它不是精确训练结束时间，更不是所有训练语料的知识截止日期。Hub `createdAt` 是仓库创建时间，`lastModified` 是仓库更新，二者都不能直接替代模型首发或训练 cutoff。公告首发与历史上传日期不同是正常现象，须各自标清。

已部署 Ollama Qwen 7B 与 Llama 8B 的 digest 在 [server-model-execution.md](server-model-execution.md)；它们证明实际分发文件身份，不独立证明 GGUF 与原 tensor 的转换关系。本次 Llama 的最新 Hub config 仍需鉴权而返回 401；没有假装下载并校验该 config 或新增历史 tensor 认证。新模型执行时优先从上述固定原版 revision 转换，并固定 llama.cpp 转换/量化工具 commit；或者选择出处、原 revision、转换过程明确的官方 GGUF。转换后的每个文件 SHA256、模型 manifest、tokenizer 与 chat template 一并保存。

## 4. 共同实验条件

| 条件 | 首轮固定策略 |
|---|---|
| 题库 | 120 篇独立源文章，中文60/英文60；20篇开发、100篇隐藏测试；目标每篇8题，共960题，正式800题 |
| 正式输入 | 每模型相同正文、段落 ID、问题、选项与规则；标题/日期是否呈现统一声明；不向模型发送答案、金标、评分规则实例中的测试答案 |
| 上下文 | 各模型共同 8,192 token；逐模型用其冻结 tokenizer 和原生模板核算真实长度，输出预算512，余量预留512；任一模型超限的文章统一处理或排除 |
| 长文本 | 正式集冻结前定义完整文章或连贯节选，不按金标“只摘出答案”；保留全文、节选映射和 hash，不静默截断、不默认做 RAG |
| 提示与模板 | 相同任务指令和零样本政策；各模型使用官方原生 chat template，固定其hash。不要把 Qwen 的 ChatML 特殊 token 强塞给 Mistral。模型不支持独立system时按同一政策把同一指令并入首条user，记录最终token序列 |
| 采样 | greedy/temperature 0；能接收时记录seed42；无beam、自洽、多候选或私下重试选择最好答案 |
| 输出格式 | 统一答案、证据ID、拒答和置信度契约；统一是否使用JSON约束。约束方式不兼容的模型不得一部分使用语法约束、一部分完全自由生成而不披露 |
| 能力与工程 | 正式端到端计入格式失败，同时另报有效输出子集成绩与覆盖率；开发阶段检查格式导致的假低分。能力读数不能只用删去失败后的高分 |
| 模型 | 通用dense Instruct/Chat；同一种 Q4_K_M 量化政策、固定转换版本；单模型驻留、单请求并发。保存实际量化和设备，不能只靠tag名称 |
| 外部信息 | 关闭联网、检索、tools、RAG、对话历史、适配器和在线学习。所有模型无跨题记忆，文章不得留在前一题聊天历史里 |
| 评分 | 冻结金标与评分版本；双语分别报选择题Accuracy、短答EM/F1、数值正确率、证据集合EM/F1、D6拒答/误答及Brier；项目段落严格联合J与D1—D5自定义U作为补充，速度独列。口径以[研究总计划](research-and-experiment-plan-20261013.md)为准 |

8K 是共同预算，不宣称测量各模型最大长上下文能力。当前平台旧接口的 6,000 UTF-8 字节保守限制尚不足以代表 tokenizer 预算；需要 v2 真实模型运行路径升级或明确节选后才能执行本计划。现有离线 v2 评分器不等于完整 v2 模型接口已接入。

相同 `Q4_K_M` 名称不保证每个模型损失相同。附加稳健性实验：选开发集80道双语、各维题目，给 Qwen7B 与 Mistral7B 各运行一种更高精度（优先BF16，资源不足则统一Q8），与已有Q4同题结果配对。若量化造成明显排序变化，报告部署精度下的成绩，并把更高精度差异单列；不在隐藏测试结果出来后随意更换精度挑高分。

## 5. 执行顺序与请求预算

| 阶段 | 数据与模型 | 计划请求量 | 完成条件 |
|---|---|---:|---|
| 身份和资源预检 | 六模型元数据、许可、GPU/CUDA/磁盘 | 不调用模型 | 历史源权重与新量化清单冻结；目标GPU可以实际推理 |
| 小批接口检查 | 每模型12题，中文6/英文6，覆盖可答/拒答、证据与数值 | 72 | 合法响应、预算、日志、取消/恢复可验证；不得称阅读排名 |
| 开发评测 | 20篇、160道已审定开发题，每模型一次 | 960 | 冻结共用prompt、输出/上下文预算，记录逐模型长度和耗时；不以隐藏题调参 |
| 正式主比较 | 100篇、800题，每模型一次，首轮六款 | 4,800 | 六模型完全相同的隐藏题清单；失败计入预定分母；导出逐题结果 |
| 可选Llama参照 | 同一正式800题；如完整执行开发与诊断则统一扩展全阶段 | 正式再加800；开发160和诊断80另计 | 单独标明8B、语言覆盖与权重出处，七模型共5,600正式请求；完整四阶段额外1,040次 |
| 记忆与文本依赖诊断 | 预选60个正式可答题的无正文版本（中文30/英文30）；另20个开发反事实案例（中文10/英文10），原文结果复用开发运行，只新增改文条件 | 六模型共480（360+120） | 冻结选择与改写金标；无正文只比较答案、不评分不存在的文本证据；分析旧知识作答与跟随文本变化，诊断结果独列 |
| 精度稳健性 | 开发集80题，Qwen7B/Mistral7B各一种更高精度 | 160额外请求 | 与Q4同题比较，固定转换与设备；不用于隐藏集规则调优 |

开发＋正式＋两类诊断共6,240次，接口72次和精度160次另列，合计6,472次，不含可选Llama和非确定性重复。若不执行诊断和精度附加项目，接口＋开发＋正式共5,832次。若正式集最终题数改变，按“正式题数×模型数”重新计算，不能把候选编题目标当已完成实验。

CPU 当前适合接口演示和小样本。以前仅一篇小实验的 CPU 平均耗时约38—48秒/请求；假设4,800次都维持这个速度，纯串行就约51—64小时，这不是长文/14B的测得工期，实际可能更长。不要据此承诺当晚完成。GPU用开发集实际测得的平均/p95耗时与token吞吐估算各模型工时：`正式题数 × 该模型分层平均耗时`，加加载、冷启动、检查与失败处理。主性能统计采用预先规定的热运行；冷加载耗时另报。

阶段排序为：先完成题库日期/重复/权利审核与20篇开发金标，完成统一 v2 运行接口，再建立六模型最小检查；然后用开发集估时与冻结条件，最后一次性封存正式清单并批量跑。独立人员审题签名不能用 AI 自评或自动生成代替，隐藏集题目也不拿来做示例提示。

## 6. 3090 资源与部署边界

2026-10-11记录是四卡已有任务且只能用CPU；这不是当前状态。2026-10-13只读复查 [server-gpu-readonly-20261013.txt](../output/server-gpu-readonly-20261013.txt) 显示GPU 0、1、3为RTX3090：总24,576MiB，报告空闲24,124MiB，利用率0%。GPU2枚举有异常，本次没有重置它或修改驱动。CUDA初始化与真实GPU模型调用尚未在此次复查中验证，所以只能说0/1/3是候选可用卡。

首轮选一张通过CUDA检查和最小真实推理的空闲卡，六模型依次加载，每次单模型、单并发。执行前重新检查显存和其他compute进程；不终止别人的服务，也不沿用过期空闲快照。多张健康卡以后可以执行独立辅助任务，但延迟主比较用相同型号、可比空闲状态、相同运行软件；不能把一个模型CPU、一个模型GPU的延迟当模型本身速度比较。

以Qwen14B为例，原始BF16权重约 `14.77B × 2 bytes = 29.54 GB ≈ 27.51 GiB`，仅权重已超过单3090显存。Q4原始数据下界约7.39GB，实际Q4_K_M还有量化尺度和部分高精度tensor；可先按8—10GB权重作容量估计，但应以下载后的实际文件和运行占用替代估计。8K、batch1、FP16 KV cache 的理论占用约1.5GiB，加2—4GiB工作缓冲后，单张完整空闲3090可作为Q4可行候选，仍需真实试运行。

KV估算公式为 `序列长度 × 层数 × 2(K,V) × KV头数 × 每头维度 × 每元素字节数`。Qwen14B用48层、8个KV头、128维、2字节；这里不含框架预分配、CUDA图、并发或额外缓存。内存容纳不等于吞吐达标。

Qwen7B/Mistral7B BF16原权重约14.2/13.5GiB，单请求8K KV约0.44/1GiB，在完整空闲3090上有机会完成精度附加实验；启动仍以实测峰值为准。32B暂列下一轮：单24GB卡的Q4权重与缓存余量有限，多GPU引入通信和实现差异，本轮不必为了参数曲线强行部署。模型下载继续使用项目专属目录 `/home/jmy/reading-bench/runtime/models` 或其固定revision子目录，不写公共模型目录。

## 7. 比较与报告

- 预先指定主要配对：Qwen1.5→3、3→7、7→14；同档位Qwen7↔Mistral7、Qwen7↔InternLM7。各配对中英文分别报告差值、题/源文章覆盖和按源文章簇bootstrap的95%区间，避免把同文8题当8个独立样本。
- 五个主要配对的推断如同时做显著性检验，应声明检验族并校正多重比较；本轮以效应量和区间为主。探索性语言/领域/长度结果明确标注，分层过小不得作稳定总体排名。
- 主表：模型实际参数、版本/量化，中英文分别列选择题Accuracy、短答EM/F1、数值正确率、证据EM/F1、D6平衡准确率和错误率，报告预指定模型配对差值与区间。补充表列项目严格联合J、自定义U及各维度；资源表单列p50/p95时延、输入/输出tokens和峰值显存。不同题型的分数不混成通用阅读尺度。
- 同语言同题集比较为主。中英文题库并非自动等难，语言分差不能只归因为语言能力；不存在某个维度覆盖时完整U显示N/A。
- 无正文能够答对可能是旧事实、题面线索、偶然猜测或泄漏，不能单凭它断言训练污染；提供正文后的提升也不能直接证明纯阅读因果效果。反事实诊断检查是否跟随改文，但其人工改写材料独列，不算新增真实文章。
- 输出保留完整预定清单、缺失/失败记录、原始响应、最终prompt及tokenizer/template hash、权重/运行版本、评分版本、文章hash和随机种子。只公布固定模型在固定实验条件下的结论。
